# TeamFinder

TeamFinder — учебный Django-проект для поиска участников в pet-проекты.

Проект реализован для **варианта №3**:  
**необходимые навыки проектов и фильтрация проектов по навыкам**.

---

## Стек

- Python 3.10+
- Django 5.2
- PostgreSQL 16
- Docker Compose
- Pillow
- python-decouple

---

## Что реализовано

### Пользователи

- регистрация пользователя;
- вход по email и паролю;
- выход из аккаунта;
- публичная страница пользователя;
- редактирование профиля;
- смена пароля;
- список пользователей с пагинацией по 12 пользователей на странице.

### Проекты

- список всех проектов;
- страница проекта;
- создание проекта;
- редактирование проекта автором;
- завершение проекта автором;
- участие и отказ от участия в чужом проекте;
- список участников проекта для автора;
- пагинация проектов по 12 проектов на странице.

### Вариант №3

- модель `Skill`;
- у проекта есть необходимые навыки `skills`;
- автор проекта может добавлять навыки проекту без перезагрузки страницы;
- автор проекта может удалять навыки проекта без перезагрузки страницы;
- работает автодополнение навыков;
- можно создать новый навык из интерфейса;
- на странице списка проектов есть фильтрация по навыку через GET-параметр `?skill=...`;
- активный фильтр подсвечивается;
- есть кнопка сброса фильтра.

---

## Что не реализовано намеренно

Проект выполнен для **варианта №3**.

Поэтому функциональность, относящаяся к другим вариантам, не входит в основной сценарий:

- избранное проектов относится к варианту №1;
- навыки пользователей относятся к варианту №2.

В варианте №3 реализованы именно **навыки проектов** и **фильтрация проектов по необходимым навыкам**.

## Основные URL

### Проекты

| URL | Назначение |
|---|---|
| `/` | редирект на `/projects/list/` |
| `/project/list/` | совместимый редирект на `/projects/list/` |
| `/projects/list/` | список проектов |
| `/projects/<id>/` | страница проекта |
| `/projects/create-project/` | создание проекта |
| `/projects/<id>/edit/` | редактирование проекта |
| `/projects/<id>/complete/` | завершение проекта |
| `/projects/<id>/toggle-participate` | участие / отказ от участия |
| `/projects/skills/?q=...` | поиск навыков для автодополнения |
| `/projects/<id>/skills/add` | добавление навыка к проекту |
| `/projects/<id>/skills/<skill_id>/remove/` | удаление навыка у проекта |

### Пользователи

| URL | Назначение |
|---|---|
| `/users/list/` | список пользователей |
| `/users/<id>/` | профиль пользователя |
| `/users/register/` | регистрация |
| `/users/login/` | вход |
| `/users/logout/` | выход |
| `/users/edit/` | редактирование профиля |
| `/users/password/` | смена пароля |

### Админ-панель

| URL | Назначение |
|---|---|
| `/admin/` | админ-панель Django |

## Переменные окружения

Перед запуском нужно создать файл `.env` в корне проекта.

Пример `.env`:

```env
DJANGO_SECRET_KEY=replace-me
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,[::1]

POSTGRES_DB=team_finder
POSTGRES_USER=team_finder
POSTGRES_PASSWORD=team_finder
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5436

TASK_VERSION=3
```

Описание переменных:

| Переменная | Назначение |
|---|---|
| `DJANGO_SECRET_KEY` | секретный ключ Django |
| `DJANGO_DEBUG` | режим отладки |
| `DJANGO_ALLOWED_HOSTS` | разрешённые хосты |
| `POSTGRES_DB` | имя базы данных |
| `POSTGRES_USER` | пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | пароль PostgreSQL |
| `POSTGRES_HOST` | хост PostgreSQL |
| `POSTGRES_PORT` | порт PostgreSQL |
| `TASK_VERSION` | номер варианта задания |

Для этого проекта нужно использовать:

```env
TASK_VERSION=3
```

Файл `.env` нельзя коммитить в репозиторий.

## Запуск проекта

### 1. Создать виртуальное окружение

Windows PowerShell:

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1
```

Windows cmd:

```bash
python -m venv .venv
.venv\Scripts\activate
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

---

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

---

### 3. Запустить PostgreSQL через Docker Compose

В проекте используется PostgreSQL в Docker-контейнере.

Запуск:

```bash
docker compose up -d
```

По умолчанию база данных доступна на:

```text
127.0.0.1:5436
```

Данные PostgreSQL сохраняются в Docker volume, поэтому не теряются при обычном перезапуске контейнера.

Остановить контейнер без удаления данных:

```bash
docker compose down
```

---

### 4. Применить миграции

```bash
python manage.py makemigrations
python manage.py migrate
```

---

### 5. Создать тестовые данные для ревью

В проекте есть management command, который создаёт несколько тестовых пользователей, проекты и навыки:

```bash
python manage.py create_demo_data
```

Команду можно запускать повторно.

Будут созданы тестовые пользователи:

| Email | Пароль |
|---|---|
| `anna@example.com` | `Testpass123!` |
| `petr@example.com` | `Testpass123!` |
| `maria@example.com` | `Testpass123!` |

У каждого тестового пользователя создаётся минимум один проект.

---

### 6. Создать администратора

```bash
python manage.py createsuperuser
```

Так как в проекте используется кастомная модель пользователя, при создании администратора нужно указать:

- email;
- имя;
- фамилию;
- пароль.

---

### 7. Запустить сервер разработки

```bash
python manage.py runserver
```

После запуска проект будет доступен по адресу:

```text
http://127.0.0.1:8000/
```

## Быстрая проверка для ревьюера

### Регистрация и вход

1. Открыть `/users/register/`.
2. Зарегистрировать пользователя.
3. После успешной регистрации пользователь перенаправляется на страницу входа.
4. Войти через `/users/login/` по email и паролю.
5. Проверить выход через меню пользователя.

---

### Профиль пользователя

1. Открыть профиль пользователя.
2. Проверить отображение:
   - имени;
   - фамилии;
   - аватара;
   - описания;
   - email;
   - телефона;
   - GitHub.
3. Открыть редактирование профиля.
4. Изменить данные.
5. Нажать «Сохранить».
6. Проверить, что изменения отобразились в профиле.

---

### Список пользователей

1. Открыть `/users/list/`.
2. Проверить карточки пользователей.
3. Проверить кнопку «Посмотреть контакты».
4. Проверить пагинацию, если пользователей больше 12.
5. Пользователи сортируются по дате регистрации: новые сверху.

---

### Создание проекта

1. Авторизоваться.
2. Нажать «Создать проект».
3. Заполнить форму проекта.
4. Нажать «Опубликовать».
5. Проверить редирект на страницу созданного проекта.
6. Проверить, что текущий пользователь стал автором проекта и участником проекта.

---

### Редактирование проекта

1. Открыть свой проект.
2. Нажать «Редактировать».
3. Проверить, что поля формы предзаполнены.
4. Изменить данные.
5. Нажать «Сохранить изменения».
6. Проверить редирект на страницу проекта.

---

### Завершение проекта

1. Открыть свой открытый проект.
2. Нажать «Завершить проект».
3. Проверить, что статус проекта стал `closed`.

---

### Участие в проекте

1. Войти под другим пользователем.
2. Открыть чужой открытый проект.
3. Нажать «Участвовать».
4. Проверить, что пользователь добавился в участники.
5. Нажать «Отказаться от участия».
6. Проверить, что пользователь удалился из участников.

---

### Навыки проекта — вариант №3

1. Авторизоваться как автор проекта.
2. Открыть страницу своего проекта.
3. Проверить блок «Необходимые навыки».
4. Нажать «+ Добавить навык».
5. Начать вводить название навыка.
6. Проверить автодополнение.
7. Добавить существующий навык.
8. Создать новый навык.
9. Удалить навык.
10. Проверить, что добавление и удаление работают без перезагрузки страницы.

---

### Фильтрация проектов по навыкам

1. Открыть `/projects/list/`.
2. Проверить панель фильтрации по навыкам.
3. Нажать на навык.
4. Проверить URL вида:

```text
/projects/list/?skill=Python
```

5. Проверить, что в списке остались только проекты с выбранным навыком.
6. Проверить, что активный фильтр подсвечен.
7. Нажать «Сбросить».

## Права доступа

### Гость

Гость может:

- просматривать список проектов;
- просматривать страницы проектов;
- просматривать профили пользователей;
- открыть страницу регистрации;
- открыть страницу входа.

Гость не может:

- создавать проекты;
- редактировать проекты;
- завершать проекты;
- присоединяться к проектам;
- редактировать профиль.

---

### Авторизованный пользователь

Авторизованный пользователь может:

- создавать проекты;
- редактировать свои проекты;
- завершать свои проекты;
- присоединяться к чужим открытым проектам;
- отказываться от участия;
- редактировать свой профиль;
- менять пароль.

---

### Администратор

Администратор имеет полные права на управление данными через Django admin:

```text
/admin/
```

Администратор может:

- создавать пользователей;
- редактировать пользователей;
- блокировать пользователей;
- удалять пользователей;
- создавать проекты;
- редактировать проекты;
- удалять проекты;
- управлять навыками.
